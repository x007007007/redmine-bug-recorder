# Bug Recorder for Redmine 需求文档

版本：0.2.4  
读者：测试人员、插件维护者

本文描述插件必须做到的事。实现结构见 [设计文档](设计文档.md)，尚未收口的取舍见 [设计问题](设计问题.md)。

## 1. 目标

测试人员在真实页面上操作时，插件在本机记下操作、截图、接口、Vue/Pinia 与 Console。测试人员勾选并改完描述后，才把这份材料提交到自己的 Redmine。

录制数据默认不出本机。未点击「提交到 Redmine」之前，不向 Redmine 或任何其它服务器上传会话内容。

## 2. 角色

| 角色 | 要做的事 |
| --- | --- |
| 测试人员 | 开始/停止录制，review 步骤，提交或更新 issue |
| Redmine 账号 | 提供 API Key；只能看到自己有权限的项目 |
| 维护者 | 构建 Chrome / Firefox 包，保证报告文案与截图文件名一致 |

## 3. 范围内

- Chrome MV3 与 Firefox MV3（Firefox 142+）
- HTTP/HTTPS 页面上的点击、输入、选择、提交、跳转
- 跨标签页记录
- 管理页、弹窗、DevTools 面板三处入口
- 提交到已配置的 Redmine，或更新本会话已经提交过的 issue

不在范围内：自动脱敏、录屏、Jira/禅道、把数据同步到其它机器。

## 4. 功能需求

### FR-1 录制开关

测试人员可以从管理页、弹窗或 DevTools 面板开始、停止录制。同一时间只有一个进行中的会话。再次开始时沿用当前会话，不另开一条。

停止后会话状态变为 `stopped`，并记下结束时间。

### FR-2 操作步骤

录制中的页面要记下这些步骤：

| 种类 | 触发 | 文案要求 |
| --- | --- | --- |
| navigate | 开始录制时的当前页，以及地址变化 | `打开页面 {url}` |
| click | 点击 | `点击「{标签或选择器}」`，并记下视口坐标 |
| input | 文本输入停止约 700ms、下拉、勾选 | 输入值原样写入；勾选写「勾选 / 取消勾选」 |
| keypress | 回车、Esc | 回车写成「按下 回车 键」 |
| submit | 表单提交 | 带上表单标签；有字段摘要时一并写入 |

同一输入框连续输入合并成一步。按回车或 Esc 时，先落上尚未刷出的输入，再单独记按键。

修改意见写在扩展自己的窗口里，不插入被测页面，因此不会记成用户操作。

值只做长度截断，不打码。密码字段同样原样保留，由提交前的 review 决定是否删掉。

### FR-3 截图

每次记下的操作，在约 380ms 后截取**当时可见标签页**的可视区域，存 JPEG data URL。

若这段等待里用户已经切走该标签页，这一步不截图。少一张图，也不能把别的页面截进来。

浏览器内部页（`chrome://` 等）截不到时跳过，步骤本身仍保留。

### FR-4 页面内上下文

Chrome 上、且测试人员打开了对应开关时：

- 请求：方法、URL、状态码、耗时；打开「捕获请求响应体」后额外记请求体、响应体（二进制不落库）
- Console：`log` / `info` / `warning` / `error`，以及未捕获异常
- Vue 3：组件名、组件链、点击时 props
- Pinia：`$subscribe` 变更与 `$onAction` 调用

生产构建拿不到组件实例时，步骤退回普通记录，Pinia 仍按探针结果记。

Firefox 没有 `chrome.debugger`。响应体与 Console 捕获不作为 Firefox 的验收项。请求元数据仍要记。

### FR-5 捕获开关

录制过程中可以单独开关：点击、截图、键盘、Vue、Console、请求。请求还可以切「仅当前标签页 / 全部标签页」。

下列请求不进会话：

- 扩展自己发出的请求
- 发往已配置 Redmine 根地址的请求
- `tabId < 0` 的浏览器内部请求
- 「仅当前标签页」时，不是当前活动标签页的请求

### FR-6 修改意见

测试人员可以针对页面上的元素写下要改成什么。表单是浏览器弹出的扩展窗口，不盖在被测页面上。一条意见只保留：页面 URL、元素定位（选择器、文案、Vue 提示）、意见正文、时间。

### FR-7 会话与时间线

一次录制是一条会话。会话里的操作、请求、Pinia、Console、修改意见按时间放进「大步骤」。

大步骤的边界是**去掉 hash 后的地址**。同一次打开里，地址（忽略 hash）没变的跳转不另开大步骤。

大步骤内部按时间交错。时间相同则按：操作、修改意见、Pinia、Console、请求。

管理页默认最新的大步骤在前。搜索只过滤页面，不改页内顺序。描述和提交始终按时间正序，不受界面排序影响。

### FR-8 勾选、删除与范围

- 每条小步骤可以勾选或删除；DevTools 里可以按大步骤整页勾选
- 管理页与 DevTools 的勾选通过本机 storage 同步
- 提交页默认只取最近 100 步。步数不超过 100 时给出全部
- DevTools 框选的时间区间优先于「最近 100 步」
- 测试人员可以改看全部，再恢复默认范围
- 未勾选步骤所拥有的请求、Pinia、Console、修改意见不进入 CSV 和提交材料

### FR-9 报告

提交描述为 Markdown，至少包含：

1. **操作步骤**：大步骤标题（地址、标题、起止时间）、步骤文案、选择器、截图文件名、Vue 组件与 props 变化、该步之后的 API / Pinia
2. **修改意见**：按页面分组；没有意见时写明「本次没有修改意见」
3. **环境信息**：记录起止时间；有则写 User-Agent 与最后页面
4. **Console**：步骤时间线里保留各级日志；文末「Console 错误 / 警告」只收 error 与 warning，最多 50 条

状态码 ≥ 400 的接口在描述里标出。截图文件名与实际上传文件名使用同一套规则：`step-01.jpg` 起，有点击坐标的为 `.png`。

issue 标题形如：`[Bug Recorder] {主机} {第一条非跳转步骤} @ {开始时间}`。

### FR-10 提交 Redmine

设置项：站点根地址、API Key、项目、跟踪、优先级。地址可以不写协议，按 `https://` 补齐。用户粘贴的 `/projects/...`、`/issues/...`、`/my/account` 等页面路径要剥掉，保留真正的站点根（含 `/redmine` 这类子路径）。

提交流程：

1. 可选上传截图。先 `POST /uploads.json`，404 再试 `POST /uploads`
2. 可选上传 CSV（UTF-8 BOM，Excel 可直接打开）
3. 没有指定已有 issue 时 `POST /issues.json`；指定了则 `PUT` 更新，并在会话里累计修订次数
4. 截图张数可限，超出时保留最近的若干张
5. 有点击坐标的图在上传前烙上半透明标记；烙失败则退回原 JPEG

API Key 放在 `X-Redmine-API-Key`。若返回 401，改用查询参数 `key` 再试一次。错误信息里不得留下 API Key。

项目列表走 `GET /projects.json`。该地址 404 时，再用当前用户的成员关系取可提交项目。列表为空时仍允许手填项目标识或数字 ID。

### FR-11 本机存储

会话、步骤、请求、日志、Pinia、修改意见存在本机 IndexedDB（库名 `bug-recorder`）。设置与 API Key 存在 `storage.local`，不随账号同步到其它机器。

删除会话时，其步骤与关联记录一并删除。

## 5. 非功能需求

| 编号 | 要求 |
| --- | --- |
| NFR-1 | 源码 TypeScript strict。`npm run typecheck` 与 `npm test` 必须通过 |
| NFR-2 | 浏览器加载的是 `dist/`。内容脚本打成 IIFE，后台与页面脚本打成 ESM |
| NFR-3 | 单文件原则上不超过 200 行，共享逻辑放在 `shared/`，避免页面和后台各写一份 |
| NFR-4 | 许可为 PolyForm Noncommercial 1.0.0。非商业使用可以;商业使用须先取得作者书面授权 |
| NFR-5 | Chrome 扩展 ID 与 Firefox 附加组件 ID 保持现有固定值，升级不能换 ID |

## 6. 验收

逻辑规则由 `npm test` 覆盖，对应关系：

| 需求 | 测试文件 |
| --- | --- |
| FR-2 文案、FR-9 标题 | `tests/describe.test.ts` |
| FR-7 大步骤、勾选归属、过滤 | `tests/timeline.test.ts` |
| FR-8 最近 100 步与时间选区 | `tests/scope.test.ts` |
| FR-9 描述、FR-10 截图命名与 CSV | `tests/report.test.ts` |
| FR-5 请求过滤 | `tests/capture.test.ts` |
| FR-10 地址整理与 API 回退 | `tests/redmine.test.ts` |
| FR-4 探针序列化 | `tests/serialize.test.ts` |

需要浏览器、演示页和假 Redmine 的链路仍走 `npm run smoke`（见仓库根目录 README）。单元测试不启动浏览器，也不能代替冒烟。
