# 设计问题

版本：0.2.4  
这里记录已经落地、但还没有收口的设计取舍。需求见 [需求文档](需求文档.md)，当前实现见 [设计文档](设计文档.md)。

每条包含：现在怎么做、为什么先这样、还没决定什么。

## DQ-1 大步骤忽略 hash

**现在：** `pageUrl` 去掉 hash。`https://app/index.html#/orders` 和 `#/login` 算同一大步骤。同 URL 的 navigate 直接丢弃。

**原因：** 带锚点的刷新和重复 `load` 会把一页切成很多段，复现步骤难读。

**未决：** 使用 hash 路由的站点，登录页和业务页会被并进同一大步骤，时间窗也会把后半段接口算进前一个「页面」。若要支持，边界应改成「hash 路由模式」开关，而不是全局把 hash 当路径。默认仍应忽略普通锚点。

## DQ-2 截图故意晚 380ms，并且可以缺席

**现在：** 步骤先落库，约 380ms 后再截可见标签。标签已经切走就不截。

**原因：** 立刻截会拍到点击前的画面。切走再截会把 B 页的图像挂到 A 页的步骤上。

**未决：** 点击后立刻整页跳转的那一步，经常没有图。没有「跳转前强制截一张」的补偿。补偿必须仍然绑定原标签，不能改成截当前可见页。

## DQ-3 输入按 700ms 合并

**现在：** 每个文本框各自防抖。回车 / Esc 会立刻冲刷。切换焦点不会冲刷上一个框。

**原因：** 每个按键记一步无法阅读。

**未决：** 测试人员打完字立刻点按钮时，输入步骤可能比点击步骤晚到（点击在 0ms，输入在 700ms）。时间线会显示成「先点后输入」。可选做法是在下一次点击前冲刷所有未完成的输入。尚未改，因为冲刷点要定义在内容脚本里，和点击监听的顺序绑在一起。

## DQ-4 原始值不做脱敏

**现在：** 密码、请求体、Pinia、截图都原样进本机 IndexedDB。只有提交时才把勾选内容发到测试人员自己的 Redmine。

**原因：** 缺陷单需要真实入参。自动打码会把「密码填错」和「字段没提交」一起抹掉。

**未决：** 本机数据库对同一系统用户的其它进程仍是可读的。没有「提交前扫描密码字段并默认不勾选」的保护。若要加，只能做成提交页的默认勾选策略，不能在采集时丢值。

## DQ-5 API Key 会进入查询串

**现在：** 首选请求头 `X-Redmine-API-Key`。401 时改试 `?key=`。GET 404 时去掉自定义头再试 `?key=`。抛出的错误会删掉查询串里的 `key`。

**原因：** 一部分反代丢掉不认识的头，或看见这个头直接 404。Redmine 官方允许查询参数。

**未决：** 回退成功时，Key 会出现在 Redmine 或网关的访问日志里。插件侧没有单独的「禁止查询参数回退」开关。需要给设置加一个明确的开关，而不是悄悄停用回退。

## DQ-6 响应体和 Console 只有 Chrome 完整

**现在：** 元数据走 `webRequest`，两种浏览器都有。响应体和页面 Console 走 `chrome.debugger`，Firefox 构建不声明该权限。

**原因：** Firefox MV3 没有等价的 debugger 抓包。主世界 console hook 能覆盖一部分 `console.*`，覆盖不了网络响应体。

**未决：** Firefox 上的缺陷单会稳定缺少响应体。产品上要不要在 Firefox 提交结果里写一行「本次环境未捕获响应体」，避免阅读的人以为接口没有返回。

## DQ-7 Vue 组件信息依赖开发构建

**现在：** 探针读 `el.__vueParentComponent`。读不到就当普通步骤。Pinia 走另一路，不依赖这条链。

**原因：** 生产构建会丢掉组件名和实例标记。没有稳定的公开 API 可以在任意站点上打开。

**未决：** 生产包站点上，组件链整段为空，props diff 也不会出现。不打算为生产构建做源码映射。文档和提交说明需要让测试人员知道：要对组件名，就测 dev/Vite 构建。

## DQ-8 props diff 只比较字符串

**现在：** 每个组件记住上一份 props JSON。两边都能 `JSON.parse` 时，按键比较字符串是否相同，最多 8 条。

**原因：** 探针已经把每个 prop 收成短字符串，diff 不再碰到 Vue 的响应式对象。

**未决：** 解析失败时这份快照不产生 diff，但会成为下一次的「上一份」。中间一次坏 JSON 会让下一次对比失去基准。另外，对象类型的 prop 在探针里已经是字符串，深层字段变化只要字符串不同就能看见；字符串被截断后，尾部变化会显示成没变。

## DQ-9 「最近 100 步」按数组尾巴切

**现在：** 没选时间区间且步骤超过 100 时，保留 `actions` 数组的最后 100 条，再用第一条的 `ts` 当窗口起点去裁请求和意见。

**原因：** 长会话直接铺到提交页会无法 review，也容易把截图传爆。

**未决：** 这里的「最近」是存储顺序的末尾，不是按 `ts` 重排后的末尾。若补录或跨标签导致数组顺序和 `ts` 不一致，窗口会裁错。时间选区那条路径是按 `ts` 闭区间切的，两套语义不一致。收口方式应是默认范围也先按 `ts` 排序再取末尾。

## DQ-10 事件归属可能跨页

**现在：** 请求落在哪个大步骤，看它的 `ts` 落在哪个 `[startTs, nextStartTs)`。勾选归属则看「不晚于该时间的最后一条步骤」，这条规则不看页面。

**原因：** 接口没有「是哪次点击发出的」这个因果字段，只能用时间近似。

**未决：** 页面刚切开时，上一页的慢请求会显示在下一页下面，勾选下一页的第一步也会把它带走。要改进只能在请求上额外记下发起时的 `tabId` + 页面 URL，而不是继续把阈值调松。

## DQ-11 点击标记会改上传图

**现在：** 有坐标的步骤上传 PNG，并在像素上画红色圆圈。绘制失败才回退原 JPEG。界面缩略图用 CSS 叠加，不改 data URL。

**原因：** Redmine 上看图的人没有插件的叠加层。

**未决：** 上传件不再是原始截图，圈的位置依赖视口尺寸换算。页面在 380ms 内滚动后，圈会偏。是否同时再附一张无标记原图，尚未定；双份附件和「最多 N 张」的计数方式要一起定。

## DQ-12 CSV 把截图 base64 放进单元格

**现在：** CSV 十列，最后一列是截图 base64，单元格做了引号转义。提交件另加 BOM。

**原因：** 希望一个文件就能在 Excel 里看到步骤和接口，不依赖 Redmine 附件。

**未决：** 几十张 JPEG 的 base64 会让 CSV 大到 Excel 打不开，也和「截图限量」互不相干——限量只作用于上传的图片，不作用于 CSV 列。应决定 CSV 是否服从同一个 `shotLimit`，或者默认不内嵌图、只在勾选时内嵌。

## DQ-13 勾选同步没有版本

**现在：** 管理页和 DevTools 把勾选 id 写入 `storage.session`，对方读到就覆盖本地集合。

**原因：** 测试人员会在两个界面来回勾。

**未决：** 没有修订号。两边同时改时，后写入的整表覆盖先写入的。收口需要带 `selectionRev` 的合并，而不是最后一次 `set` 赢。

## DQ-14 更新 issue 时不检查对方是否改过

**现在：** 同一会话再次提交走 `PUT /issues/{id}.json`，用本地正文覆盖描述，并给 `revisionCount` 加一。

**原因：** 测试人员补截图或改步骤后，应落在原来的缺陷上，而不是再开一张。

**未决：** 若有人在 Redmine 里改过描述，下一次提交会盖掉那些修改。插件没有先 `GET` 比较 `updated_on`。要做的话，冲突时应停下来让测试人员选「覆盖」或「改开新 issue」，不能静默覆盖。

## DQ-15 `/issues/{id}.json` 剥不掉

**现在：** `normalizeBase` 能去掉 `/issues/8`、`/issues.json`、`/projects/demo/issues/12`。`/issues/8.json` 整段留在路径里。

**原因：** 匹配把 `.json` 放在编号前面（`issues.json/8` 这种形状），编号后面的 `.json` 对不上。

**未决：** 测试人员若从接口地址而不是网页地址复制链接，附件接口仍会 404。修的时候只扩这一条路径的剥除，不要把业务站点自己的 `/issues/8.json` 风格路径误伤——这个函数只应用于设置里的 Redmine 根地址。
